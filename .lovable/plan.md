# Rebuild YouTube Shorts — real production, not text slides

The current Shorts are giant caps on a gradient with a progress bar. That format is dead on Shorts. This rebuild produces the format that actually works right now on the algorithm: **real product footage as the background, AI voiceover on top, word-by-word burned captions, punchy hard cuts, a music bed, and a 0.5s hook**. The pipeline generates everything server-side and gives you a finished MP4 to upload.

## What each Short will look like

- **9:16, 1080x1920, 30fps, 22–28 seconds** (algorithm sweet spot).
- **Frame 0 hook**: giant 3–5 word caption over a real scan-in-progress screenshot ("This site is broken.", "I scanned Apple.com", "Your homepage is leaking money"). No brand intro. No logo card.
- **Body (~18s)**: real recorded footage of a SiteScoper scan — URL typed in, progress bar filling, findings popping in with red flags — Ken-Burns zoomed/panned so it feels dynamic even though it's a screen-cap. Voiceover narrates one specific insight (pulled from a real `analysis_history` finding). Word-by-word captions pop in sync with the voice, TikTok-style — bold Inter Black, white with a black stroke, one word highlighted in accent color at a time.
- **End card (~2s)**: single line "sitescoper.com — free". No CTA button, no "smash subscribe". Hard cut to black.
- **Music bed**: subtle lo-fi/tech-ambient generated by ElevenLabs Music, ducked -18dB under the voice.
- **Voice**: ElevenLabs "Liam" or "Brian" (calm dev-showing-a-friend energy), `eleven_turbo_v2_5`, speed 1.05.

Five rotating formats stay, but each is now built around real footage, not text slides:
1. **I scanned [famous site]** — Playwright screen-recording of a live scan against a real URL (Apple, Stripe, Notion, etc.), voiceover calls out the first real finding.
2. **3 things wrong with your homepage** — 3 hard cuts, each on a real screenshot with an issue highlighted by a red circle animation.
3. **Before / after** — split-screen: raw site vs SiteScoper's suggestion overlay.
4. **What Lighthouse won't tell you** — Lighthouse 95 score screenshot → cut to SiteScoper flagging an SEO/CRO issue Lighthouse missed.
5. **60-second audit** — sped-up 4x recording of the full scan flow ending on the report page.

## Pipeline changes

### 1. Screen recording (new)
- New edge function `youtube-short-capture` uses **Browserless** (or ScrapingBee's screenshot API as a fallback — both already accept an API key with no infra to run) to load `sitescoper.com/?url=<target>&autorun=1`, wait 15s, and capture a 20s WebM screen recording. Requires one new secret: `BROWSERLESS_TOKEN` (I'll ask for it).
- Fallback: static high-res screenshots at 5 points during the scan, then Ken-Burns'd in the renderer.

### 2. Voiceover (ElevenLabs)
- Use the existing **ElevenLabs standard connector** (no new secret needed — I'll link it via `standard_connectors--connect` if not already linked).
- Script comes from Lovable AI (Gemini 2.5 Flash) grounded in a real recent `analysis_history` finding.
- Word-level timestamps returned by ElevenLabs drive the caption sync.

### 3. Music bed (ElevenLabs Music)
- Generate a 25s "lo-fi tech ambient, minimal, no drums" bed once per Short.
- Ducked under voice in the mix.

### 4. Renderer (Remotion, extended)
- New composition `remotion/src/YouTubeShort.tsx` (9:16, 30fps).
- Layers: base footage (video or Ken-Burns'd screenshots) → dark vignette → word-by-word caption track driven by ElevenLabs timestamps → end card → mixed audio (voice + music).
- Renders through the existing `remotion/scripts/render-remotion.mjs` flow, outputs MP4 to Supabase storage bucket `youtube-shorts`.

### 5. Admin page (`/admin/youtube`) redesign
- Preview is now the **actual rendered MP4** (with audio), not a canvas loop.
- Download gives you the real MP4 that YouTube accepts as a Short.
- Title/description/tags/hashtags all copyable, and there's a **regenerate voice**, **regenerate footage**, and **regenerate script** button independently so you don't have to redo the whole thing if one part is off.
- Music/no-music toggle per Short (per your "AI voice or captions+music only or both" answer, default is voice+music; toggle can produce a no-voice cut in one click).

### 6. Data model
- Extend `youtube_shorts` with: `video_url text`, `voice_url text`, `music_url text`, `caption_timings jsonb`, `target_site text`, `duration_seconds int`.

## Technical section (skip if not interested)

- Edge functions: `youtube-short-generate` (orchestrates: pick format → pick insight → draft script → capture footage → TTS → music → enqueue render), `youtube-short-render` (invokes Remotion via a lightweight render worker; since Remotion needs Chromium and Supabase edge functions can't run it, we render **client-side in the admin page** on demand using a hidden Remotion Player + `@remotion/renderer` fallback via a small render endpoint on Vercel/Railway if you want fully-automated). MVP: render happens in the browser when you open the admin page — takes ~30s, no extra infra.
- ElevenLabs endpoints via connector: `/v1/text-to-speech/{voice_id}?output_format=mp3_44100_128` with `output_format=mp3_44100_128` in query (per docs), and `/v1/music` for the bed.
- Captions: use ElevenLabs' word-level timestamps response (`with_timestamps=true`) to build the caption track — no manual sync.
- Cron: unchanged. 13:00 UTC daily → `youtube-short-generate` inserts a draft row. You render + download in the browser.
- Old canvas-based renderer in `AdminYoutube.tsx` is removed.
